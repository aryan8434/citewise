Build blueprint · modeled on botric.ai, Sept 2026

Citewise

An AI-visibility and AI-support platform that one developer can build in about eight weeks. It finds the questions where ChatGPT, Perplexity, Gemini and Claude leave a brand out, drafts the pages that fix those gaps, and answers the visitors that AI engines send. Citewise is a working name; rename it freely.

  • Next.js on Vercel
  • Postgres on Supabase
  • pg-boss queue
  • Node worker
  • pgvector
  • Razorpay
A buyer asks an AI engine

“best AI trip planner for India”

Good options are Rival A[1] for day-by-day itineraries and Rival B[2] for budget trips. Travo AI[3] plans the trip in chat and books flights and hotels in the same place.

export type EngineId = 'chatgpt' | 'perplexity' | 'gemini' | 'claude' | 'aio';

export interface EngineAnswer {
  engine: EngineId;
  model: string;                // exact model the API reports
  text: string;                 // the answer as a user would read it
  citations: { url: string; title?: string; position: number }[];
  latencyMs: number;
  costMicroUsd: number;         // from token + search usage; feeds the margin report
  raw: unknown;                 // full response, kept so you can re-extract later
}

export interface EngineAdapter {
  id: EngineId;
  // country and language are passed where the API supports a user location
  ask(prompt: string, opts: { country: string; language: string }): Promise<EngineAnswer>;
}

The same prompt gets a different answer on different runs. Start with one sample per prompt per engine each week, and show trends over single results. A second weekly sample makes scores steadier but doubles the engine bill; section 13 shows what that does to margins.

API answers are not identical to what someone sees in the ChatGPT app, which may use a different model and personalises results. Label results "via API" in the product so nobody is surprised.

[4]Tracking pipeline

What happens between "it's Monday" and a new score on the dashboard. Each box is a pg-boss job, and each writes its own rows.

What the extract step does

  1. Match names in code. Brand name, aliases and every rival's names, case-insensitive with word boundaries. Rank is the order in which tracked names first appear (the list position when the answer is a list).
  2. Tag each citation. Reduce the URL to its registrable domain (the tldts package does this), then compare it with the project's domain and the rivals' domains: own, rival or other. "Other" domains that keep coming up are unclaimed sources worth getting listed on.
  3. One cheap LLM call per answer with JSON output: tone toward each mentioned name from −1 to 1, factual claims made about your brand, and any other brands recommended (these become suggested rivals).
  4. Check claims against brand_facts (founding year, prices, cities served, features). A mismatch becomes a perception flag, e.g. "Gemini says Travo has no hotel booking."

Matching in code first keeps results cheap and repeatable. The LLM only judges what code can't: tone and claims.

[5]Visibility Score

One number from 0 to 100 that moves when the work is working. Score every answer, then average.

per answer = 0.40 × mentioned + 0.20 × rank points + 0.25 × cites your domain + 0.15 × tone
score = 100 × average over every answer in the week

Rank points: 1st = 1.0, 2nd = 0.8, 3rd = 0.6 … 6th or lower = 0. Tone maps −1…1 to 0…1. Rank and tone count as 0 when you aren't mentioned, so a single lucky first-place mention can't inflate the score.

// packages/scoring/visibility.ts (pure, unit-tested)
export function visibilityScore(answers: ScoredAnswer[]): number {
  if (answers.length === 0) return 0;
  const total = answers.reduce((sum, a) => {
    const rankPts = a.mentioned ? Math.max(0, 1 - (a.rank - 1) * 0.2) : 0;
    const tonePts = a.mentioned ? (a.tone + 1) / 2 : 0;
    return sum + 0.40 * +a.mentioned + 0.20 * rankPts + 0.25 * +a.citesOwnDomain + 0.15 * tonePts;
  }, 0);
  return Math.round((100 * total) / answers.length);
}

// share of voice = your mentions ÷ (your mentions + every rival's mentions)

[6]Free audit

The lead magnet and your best demo. Anyone pastes a URL and gets a report in about 30 seconds with no signup. It runs as a worker job; the page shows live progress over server-sent events.

Sitemap/sitemap.xml with recent lastmod datesHelps crawlers find new pages quickly

Audit score = 40% readiness (checks passed ÷ 6) + 60% Visibility Score on the 10 answers.

Guard rails

  • Cache the result per domain for 24 hours; a repeat request returns the saved report.
  • 3 audits per IP per day, and a Cloudflare Turnstile check before the job is queued.
  • Use the two cheapest engines. The full set is what people sign up for.
  • Public report at /r/[slug] with noindex, so shared links work without flooding search with thin pages.

[7]Content agent

Turns a gap into a draft page. It writes from what the engines already cite for that prompt, so the draft answers the same questions better instead of guessing.

  1. Pick a gap: a prompt where you are missing and a rival or a third-party page is cited.
  2. Read the winners: fetch up to 5 cited pages and keep their main text.
  3. Write a brief: the LLM lists the questions those pages answer, the facts they use, how they are structured, and what they leave out. Your brand_facts are added so the draft stays accurate.
  4. Draft: Markdown that answers the prompt in its first two sentences, then an FAQ section, a comparison table where one fits, and JSON-LD (Article and FAQPage).
  5. Review: the user edits and approves the draft in the app. Nothing publishes on its own.
  6. Publish: copy as HTML or Markdown now; push to WordPress through its REST API later.
  7. Re-test: 14 and 28 days after the user saves the live URL, the prompt is re-asked and the article card shows whether it got cited.

Cost: 100 credits per article. Step 7 is what makes the feature believable, because it ties each page to a measured result.

[8]Support agent

Engine 02. You already built its core in Travo: retrieval over a catalogue plus an LLM with a fallback. What's new is packaging it for other people's sites.

  • Sources. A sitemap URL, single URLs, or uploaded PDFs (Supabase Storage). The source.sync job crawls, cleans, splits into ~500-word chunks with overlap, embeds, and stores them in chunks tagged with the agent's id.
  • Answering. The widget posts a message; the API route embeds the question, takes the 6 closest chunks for that agent from pgvector, and streams a reply over SSE. The prompt carries the brand voice and a rule to answer only from the retrieved text, with links to the source pages.
  • Escalation. If the best match is weak or the visitor asks for a person, the widget asks for an email and sends the transcript to the team's email or Slack webhook. The conversation is marked escalated.
  • AI-referral tagging. ChatGPT adds utm_source=chatgpt.com to links it shows, and the referrer names the other engines. Each conversation stores its source, so the dashboard can show "chats from AI answers this week". This is the link between the two engines.
  • Retention. A nightly job deletes messages older than the plan's history window (60, 90 or 120 days).

[9]Crawler tracking

Botric shows when AI bots read your pages. A normal analytics script can't do this, because bots don't run JavaScript. The hit has to be caught where the request arrives: at the edge, in the server, or in the logs.

// snippets/cloudflare-worker.js: runs in front of any site on Cloudflare
const AI_BOTS = /GPTBot|OAI-SearchBot|ChatGPT-User|ClaudeBot|PerplexityBot|CCBot/i;

export default {
  async fetch(request, env, ctx) {
    const response = await fetch(request);          // serve the page as usual
    const ua = request.headers.get('user-agent') || '';
    if (AI_BOTS.test(ua)) {
      ctx.waitUntil(fetch(`${env.CITEWISE_URL}/api/ingest/crawl`, {   // report after responding
        method: 'POST',
        headers: { 'content-type': 'application/json', 'x-project-key': env.CITEWISE_KEY },
        body: JSON.stringify({
          ua,
          path: new URL(request.url).pathname,
          ip: request.headers.get('cf-connecting-ip'),
          status: response.status,
        }),
      }));
    }
    return response;
  },
};
  • Other hosts. Ship the same idea as Next.js middleware, a small WordPress plugin, and a log-file upload for everyone else.
  • Verify. Anyone can fake a user agent. Where a vendor publishes its bots' IP ranges (OpenAI and Perplexity do), the crawl.verify job marks the hit verified. Show unverified hits separately.
  • Read the signal. Training crawlers (GPTBot, CCBot) are slow-moving. User-triggered fetchers such as ChatGPT-User load a page because someone asked a question right now, which is the closest thing to a live citation.
  • Keep the list in config. Vendors add new bot names; the regex should not need a deploy.

[16]Decisions and risks

  • Official APIs only.Scraping chat apps breaks their terms and breaks often. Label results "via API".
  • The queue lives in Postgres.pg-boss means one less service than Redis, and jobs survive a worker restart.
  • Code matches names; the LLM judges tone.Cheaper, repeatable, and easy to test.
  • Keep every raw answer.Storage is cheap; re-asking the engines is not. A better extractor can be re-run over history.
  • Reserve credits before work.A ledger row per reservation and refund, so a balance can't go negative mid-run.
  • Your site passes your own audit.Server-rendered pages, llms.txt, JSON-LD. The product is its own proof.
